# SkillBuilder MySQL proxy

A tiny Node/Express service that lets the browser-based SQL sandbox run
**read-only SELECT queries** against a real, teacher-supplied MySQL
server, without ever exposing that server's host or credentials to
student browsers.

```
Student's browser --HTTPS--> this proxy --MySQL protocol--> your MySQL server
```

This is a **separate deployable service** from the main SkillBuilderApp
frontend (that one builds to static files; this one needs to stay running
as a small server).

## Why Render doesn't have a one-click MySQL option

Render offers managed Postgres, but does not currently offer managed
MySQL as a hosted database product -- only self-managed MySQL via Docker,
where you're responsible for backups and configuration yourself. This
proxy is built to work with **any** MySQL server reachable from the
internet (or from wherever you deploy this proxy): a self-hosted MySQL
instance, a school's on-prem server, a cloud VM running MySQL, or a
managed MySQL offering from another provider (PlanetScale, AWS RDS,
DigitalOcean, etc.).

## 1. Prepare your MySQL server

**Create a least-privilege account for the sandbox.** Do not use `root`
for this. Connect to your MySQL server as an admin and run:

```sql
CREATE USER 'sandbox_reader'@'%' IDENTIFIED BY 'choose-a-strong-password';
GRANT SELECT ON northwind.* TO 'sandbox_reader'@'%';
FLUSH PRIVILEGES;
```

This means even if every other safeguard failed, this account physically
cannot write to your database.

**Import the sample data.** From the main repo root:

```bash
mysql -h <your-host> -P <port> -u <admin-user> -p < ../mysql-proxy/northwind_mysql_import.sql
```

(This file is generated by `scripts/generate_northwind.py` and matches
the schema bundled into the browser's SQLite sandbox, so sandbox
challenges check correctly against either backend.)

**Open the port to this proxy.** Your MySQL server's firewall/security
group needs to allow inbound connections on its MySQL port (commonly
3306, or a custom port like the `33061` used elsewhere in this project)
from wherever you deploy this proxy service. If your MySQL server is
behind a home/school router, you may need port forwarding; if it's a
cloud VM, open the port in its security group for this proxy's outbound
IP (Render's static outbound IPs are listed in the Render dashboard for
services on paid plans; on the free tier, outbound IPs can vary, so you
may need a broader allow rule scoped specifically to this low-privilege
account).

## 2. Deploy this proxy

### Option A: Render Web Service (recommended, pairs naturally with the frontend's Render static site)

1. In the Render dashboard: **New -> Web Service**.
2. Connect this same GitHub repo.
3. Set **Root Directory** to `mysql-proxy`.
4. Build command: `npm install`
5. Start command: `npm start`
6. Add environment variables (Settings -> Environment):
   - `ALLOWED_ORIGIN` = your deployed frontend's URL (e.g.
     `https://skillbuilderapp.onrender.com`) -- restricts which site can
     call this proxy.
7. Deploy. Render gives you a URL like
   `https://skillbuilder-mysql-proxy.onrender.com`.

### Option B: Run it anywhere else that runs Node

Any platform that runs a long-lived Node process works (Railway, Fly.io,
a VM you already have, etc.) -- there's nothing Render-specific in
`server.js` itself.

## 3. Point the frontend at this proxy

In the main app's environment (Render static site -> Environment, or
local `.env.local`):

```
VITE_MYSQL_PROXY_URL=https://skillbuilder-mysql-proxy.onrender.com
```

Rebuild/redeploy the frontend after setting this. Teachers can then
configure the live MySQL connection from **Teacher Dashboard -> Configure
live MySQL server** inside the app itself -- the host/port/user/password
entered there are sent to this proxy per-request, never stored on the
proxy, and never reach the student's browser.

## Security summary

- The proxy rejects any query that isn't a single `SELECT` statement
  (`assertSelectOnly` in `server.js`), blocking writes and stacked
  statements.
- The **real** safety net is the least-privilege MySQL account from step
  1 -- treat the query-text check as a convenience, not the only
  defense.
- CORS restricts which origin can call this proxy at all
  (`ALLOWED_ORIGIN`).
- Each query gets a server-side execution timeout (`max_execution_time`)
  so a runaway query from a student can't tie up the connection
  indefinitely.
- Credentials travel from the teacher's browser to this proxy to MySQL on
  each request; they are not persisted by this proxy. The frontend
  currently stores them in the teacher's own browser's `localStorage` for
  convenience between sessions -- see the note in
  `src/context/MysqlConnectionContext.jsx` for how to move that
  server-side for a real deployment with many students.
